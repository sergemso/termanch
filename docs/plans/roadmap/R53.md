# R53 Voice input to the agent prompt (new)
Status: blocked (folded into step U.8 of docs/plans/ux-programme.md; decision 0102)
Score: V=6 T=3 R=3 S=5
Preds: none
Lane: free
Was: new (owner request 2026-10-14)

Why: prompts to an agent are long, and typing them on a phone is slow. The system keyboard's dictation key already works in the terminal's hidden input, but it is one small key among many, and it does not show that it is listening.
Do: 1. Spike first, on the owner's iPhone: does `webkitSpeechRecognition` run in the installed PWA on iOS Safari 16+, in which languages (the owner types Russian and English), and does the keyboard's own dictation reach `WordTracker` and the input log as ordinary `insertText`. If the keyboard path is enough, the step shrinks to a mic key that focuses the terminal and shows how to start dictation. 2. If the browser API works: a mic key in `KeyRow.svelte`, tap to start and tap to stop; interim text shown above the key row, final text typed into the terminal as if typed (through `typed()` so the word tracker and sticky modifiers see it), never followed by Enter. 3. Only the browser's own recognizer: no audio leaves the page to our servers and no paid speech service (guardrails `no-paid-services`, `security-secrets-handling`). The notice in the privacy step R08 says that the browser vendor may process the audio. 4. Microphone permission asked on first tap only, and a clear message when it is denied or unsupported (key hidden when the API is missing).
Done-when: unit tests cover the mapping from recognizer results to typed text (interim vs final, languages, stop on blur); the owner dictates a prompt on the iPhone and sees it in the agent input without an extra tap.
