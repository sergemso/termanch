# R60 Desktop terminal controls: compact mode with a visible way back
Status: pending
Score: V=5 T=2 R=2 S=3
Preds: R56
Lane: free
Was: desktop review 2026-10-16, D06

Class: implement · Check: client unit tests and this ticket's desktop regression scenario pass in the existing Chromium e2e CI job.
Why: The full phone key row and optional Fn keyboard remain available at desktop widths and consume vertical space even when a hardware keyboard supplies those keys.
Context: `Terminal.svelte` renders `KeyRow` without an input-capability condition; `KeyRow.svelte` includes keyboard visibility, sticky modifiers, font size and dictation. Desktop users still need paste/select/font/bell actions exposed through Fn.
Do: Offer Auto, Full and Compact terminal controls in local Settings. Auto may use pointer/hover capability but must have an override for touch laptops. Compact retains discoverable access to paste/copy/select, font, bell and dictation and a way to restore the full row. Preserve full mobile controls, refit xterm on changes, and keep focus and modifier state explicit.
Done-when: On a desktop with a fine pointer the compact choice increases terminal rows without hiding essential actions; a touch laptop can restore the full row; reload retains the choice; switching modes does not send input or recreate xterm. At 390px the full controls remain usable.

Verification ownership: in the same PR, add or extend `packages/client/e2e/desktop.mjs` with this ticket's desktop scenario (`isMobile: false`, `hasTouch: false`) and register `node e2e/desktop.mjs` in the existing e2e job in `.github/workflows/ci.yaml` if it is not already registered. Reuse the existing fixtures and isolated test-server setup; use a real server where the acceptance criteria require server behavior. The scenario must expose the original failure and pass with the change; retain existing mobile/resource/bundle checks. R36 later runs these scenarios on additional engines and is not a completion dependency for this ticket.

Evidence: Chrome component preview 2026-10-16: the full key row occupied 41px at 1024x768. Compact mode remains a proposed usability improvement, not a demonstrated functional failure.
