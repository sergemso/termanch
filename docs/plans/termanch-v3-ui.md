# Termanch Plan: v3 client UI (foundation, viewport, sessions, navigation, key row)

Decisions: 0069 (Tailwind v4 + shadcn-svelte), 0070 (sessions of all servers in one place, tabs, kill, sidebar states, soft limit 6, AppShell), 0071 (key row profiles, sticky Prefix). Guardrails: `soft-keyboard-never-hides-input`, `kill-session-needs-confirmation`, `connections-warn-never-drop`. Fact 0026 (baseline). Procedure `docs/skills/mobile-ui-device-check.md`. A fresh session needs only this file, those artifacts and the repo.

Cold start: Svelte 5 client in `packages/client` (`src/App.svelte` 412 lines of inline styles, `Terminal.svelte`, `KeyRow.svelte`, `ServerList.svelte`, `AddServerModal.svelte`, `Toast.svelte`, `src/app.css`, `src/lib/connection.ts` = one `Connection` per server, `src/lib/protocol.ts` wire types). Rust server `packages/server` (`backend.rs` has `SessionBackend` with list/create/attach and `Runner` for host mode, `sessions.rs` handles client messages, `connection.rs` does the handshake and sends `auth_ok`), shared wire types in `packages/core/src/protocol.rs` (must match `protocol.ts`). Use `npx --yes pnpm@9`. Tests: `cargo test --workspace`, `cd packages/client && npx --yes pnpm@9 test`, browser e2e `packages/client/e2e/run.mjs` (needs a release server build, `pnpm e2e:build`, Chrome via `CHROME_PATH`). The owner tests on an iPhone; CI cannot open a soft keyboard. Land each step as one squashed PR with green CI; merge only on the owner's "merge". Related: the v2 plan's B.3 (Add Server mode choice) waits for U.1 so it is not written twice.

### U.2 AppShell and the soft-keyboard fix (0070, guardrail soft-keyboard-never-hides-input) — [ ]‖
Class: implement · Needs: none · Check: `test -f packages/client/src/AppShell.svelte && cd packages/client && npx --yes pnpm@9 test`

Add a `?debug` overlay printing `innerHeight`, `visualViewport.height`, `offsetTop`, `--app-height`. 3. Make `KeyRow` part of the shell so it is pinned above the keyboard; keep `window.scrollTo(0, 0)` guards for iOS. 4. Unit test the height calculation with a faked `visualViewport`; add a browser e2e case that shrinks the viewport by a keyboard-sized amount and asserts the key row's bottom edge stays inside the visible area. 5. Ask the owner to run the device check on an iPhone (Safari and PWA) and attach screenshots.
Done-when: the unit and e2e viewport tests pass and the owner confirms on an iPhone that the key row stays visible with the keyboard open.

### U.3 Server: close_session and multiplexer info (0070, 0071) — [ ]‖
Class: implement · Needs: none · Check: `cargo test -p termanch-server -p termanch-core`
Context: `SessionBackend` in `packages/server/src/backend.rs` has `list`, `create`, `attach` only; `ClientMessage` in `packages/core/src/protocol.rs` (and `packages/client/src/lib/protocol.ts`, which must match) has no kill. `AuthOk` already carries `mode`. Host mode commands go through `Runner` so tmux queries must too.
Do: 1. Add `kill(&self, id)` to `SessionBackend`; tmux: `kill-session -t =id` through the runner, name validated with `valid_name`; `CommandBackend` gets an optional kill command (`TERMANCH_BACKEND_KILL`), absent = error "not supported". 2. Add `ClientMessage::CloseSession { session_id }` and handle it in `sessions.rs`: kill, detach the attachment if it is that session, reply with the fresh `sessions` list; write an audit entry (no content). 3. Extend `AuthOk` with `multiplexer` (`tmux`, the command backend label) and `prefix` (read with `tmux show -g prefix`, default `C-b`; empty for other backends). 4. Mirror all wire changes in `protocol.ts` and the wire-name test in `protocol.rs`. 5. Tests: kill removes the session and the list updates over WebSocket and WebRTC (extend `e2e.rs`).
Done-when: a `close_session` kills the tmux session and the next `sessions` list lacks it; `auth_ok` reports `multiplexer` and `prefix`; all Rust tests pass.

### U.4 Connection manager: all servers at once with a soft limit (0070, guardrail connections-warn-never-drop) — [ ]
Class: implement · Needs: U.1 · Check: `cd packages/client && npx --yes pnpm@9 test`
Context: `App.svelte` `connectToServer` closes the previous `Connection` and keeps `sessions`, `activeSessionId` and `connState` for one server. `Connection` (`src/lib/connection.ts`) already heals itself and pings every 5 s.
Do: 1. Create `src/lib/connections.ts`: a store holding one `Connection` per server id with its `connState`, sessions and mode; connect all at app start and when a server is added; a per-server connect/disconnect toggle that the owner controls; no automatic disconnects. 2. Pause pinging for background servers while `document.visibilityState` is hidden (already partly in `Connection.wake`; make the rule explicit and tested). 3. Show a notice with the connected count and a Manage connections action when more than 6 are connected, at app start and on add/connect, using the U.1 components. 4. Move per-server state out of `App.svelte`. 5. Unit tests with fake connections: count, threshold notice, toggle, no auto-drop.
Done-when: unit tests prove all servers connect, the notice appears only above 6, nothing disconnects without the toggle, and sessions of several servers are available from the store.

### U.5 Navigation chrome: top bar, tabs, collapsible sidebar, long-press menu (0070) — [ ]
Class: implement · Needs: U.1, U.2, U.3, U.4 · Check: `cd packages/client && npx --yes pnpm@9 test && npx --yes pnpm@9 build`
Context: Today a narrow screen shows a single "☰ session name" button and an `aside` of `min(85vw, 320px)`; wide screens have a fixed 280 px aside. Decision 0070: three sidebar states on wide screens (hidden, icon rail, full 280 px, remembered in localStorage); on a phone hidden or an overlay of about 70% width closing on tap outside, no rail; tabs mirror all sessions with a server badge, active one highlighted, no close on tabs; kill via the sidebar row close button and the long-press / right-click menu, always confirmed. Guardrail `kill-session-needs-confirmation`.
Do: 1. Rebuild the main layout inside `AppShell` with the shadcn Sidebar (grouped by server with connection status) and a top bar: sidebar toggle, scrollable tabs (session name plus server badge), New session button. 2. Context menu on tab and sidebar row, opened by long press on touch and right click on desktop, with one entry: Kill session (confirm dialog) which sends `close_session`; sidebar rows also get the close button with the same confirmation. 3. Switching a tab attaches that session on its server's connection. 4. Remove the old inline-styled aside and `narrow` header from `App.svelte`. 5. Tests: sidebar state persistence, tab list matches sessions, kill asks for confirmation and sends `close_session` only after it. 6. Owner runs the device check (long-press on iOS, overlay width, tab switching with the keyboard open).
Done-when: unit tests pass; the browser e2e kills a session through the menu; the owner confirms the long-press menu and the sidebar on an iPhone.

### U.6 Key row profiles and the Prefix key (0071) — [ ]
Class: implement · Needs: U.1, U.3 · Check: `cd packages/client && npx --yes pnpm@9 test`
Context: `KeyRow.svelte` and `src/lib/keys.ts` (`KEYS`, `applyMods`, sticky Ctrl/Alt) hold one fixed list. `auth_ok` (after U.3) carries `multiplexer` and `prefix` (for example `C-b`). herdr's real prefix is decided by v2 step B.1 (issue #22); until then the herdr profile has no Prefix key.
Do: 1. Make the key row data-driven: profiles `shell`, `tmux`, `herdr`, chosen from `auth_ok.multiplexer` of the active session's server. 2. Add a sticky Prefix key (same mechanics as sticky Ctrl in `keys.ts`): tap it, the next key gets the parsed `prefix` byte(s) prepended; a second control opens a combo menu (next/previous window, new window, split horizontal/vertical, detach, copy mode) built from the prefix. 3. Parse tmux prefix notation (`C-b`, `C-a`, `M-x`, `` ` ``) into bytes with tests. 4. Unit tests for parsing, the sticky behaviour and profile selection; browser e2e: tap Prefix then `c` creates a new tmux window.
Done-when: unit tests pass; the e2e shows a new tmux window created through the Prefix key; with a rebound prefix (`C-a`) the key sends `C-a`.
